> 注意：本文是历史记录。v147 回滚点本身仍存在的问题见文末；当前线上版本请以 `HANDOFF-v147.md` 顶部状态为准。

## Bug 1：丢光标（v147 已存在）

**用户原话**

> 不要再缝缝补补那个丢光标的问题了，想办法彻底解决，刚才又发生了

**现象**

- 输入框有时没有闪烁光标，点一下才出现。
- 窗口看起来在前台，但键盘焦点不在输入框。
- 输入框中 `document.activeElement` 有时是 `#q`，视觉上仍看不到光标。

**当时的处理**

- v148 加了 `composerCanFocus` / `focusComposer` 中央焦点管理
- v148 加了 Electron `dt:native-focus` 原生焦点桥
- v149 加了 mouseup 守卫、焦点心跳、`blur → focus` 强制重绘

**结果**

用户仍能复现，说明只修“焦点归属”还不够，选区状态和事件时序也在干扰。

## Bug 2：精确复现的丢光标（v148 ~ v149）

**用户原话**

> 选中上一个问题“补全反应”，然后CTRL C复制，中间点了几次左键，回到最底下，点追问，就丢光标了

**复现步骤**

1. 在右侧追问树里选中上一条问题的文字
2. Ctrl+C
3. 中间点几次左键
4. 滚回底部
5. 点「追问」
6. 输入框没有光标

**定位**

- 选中文字后，页面上保留了未折叠的 Selection
- `focusComposer()` 为了不打断正文选择，判断“正在选文字”，拒绝抢焦点
- 「追问」按钮里的聚焦被这条规则挡掉

**当时的处理**

- 点追问时先 `window.getSelection().removeAllRanges()`
- 再 `focusComposer({ end: true })`
- mouseup 阶段对按钮/文档项统一折叠选区并聚焦

**结果**

v149 测试能聚焦，但用户后来仍报丢焦点，说明还有其他触发路径。

## Bug 3：删除后第二次追问「点不动」（v149 ~ v150）

**用户原话**

> 删除以后重试，第二次追问点不动了，点一下输入框会出来一个表示追问的条，但是追问按钮没用了

**现象**

- 删除一条追问后，再点其他节点的「追问」
- 输入框 chip 出现，但文案始终是“回答片段 · 「整段提问」”
- 切换不同节点点追问，界面完全没变化
- 看起来按钮失效

**实际原因**

- 按钮事件本身仍在更新 `S.pendingParent`
- 但 v149 的 chip 不显示具体问题，节点也没有高亮
- 删除节点时没有清理指向已删除节点的 pending 状态

**当时的处理（v150）**

- chip 显示该追问的实际问题
- 当前追问节点加 `armed` 高亮
- 删除时如果 pending 指向被删节点，自动清空

**结果**

按钮可用性和反馈恢复；但引入了新的焦点/选区复杂度。

## Bug 4：结构图为空 + 丢焦点 + 选中回答自动挂追问（v150 ~ v151）

**用户原话**

> 结构式怎么又坏了？而且仍然丢焦点，还出现新问题，选中右边的一段文字，一松手自动变成追问这一段

这是同一轮里报的三个问题。

### 4.1 结构图为空

**现象**

化学卡片显示：

```
结构解析失败：结构图为空
```

输入框里的原始 SMILES 是空的。

**原因**

模型输出了只有 `label` / `conditions` 的化学块，没有 SMILES：

```markdown
```smiles
label: p-hydroxyazobenzene
conditions: pH 7-10, 0-5 °C
```
```

v150 会尝试把空字符串交给 RDKit，生成空 SVG，裁切时报“结构图为空”。

**当时的处理（v151）**

- 空 `smiles` / `reaction` 块不再创建化学卡片，保留原代码块
- 提示词要求没有合法 SMILES 就不要输出空化学块

### 4.2 仍然丢焦点

v150 已有中央焦点管理，但用户仍复现。说明焦点问题不是单一事件能解决的。

### 4.3 选中右侧回答文字，一松手自动变追问

**现象**

在右侧回答里选中文字，鼠标一松，输入框立即出现追问 chip，不需要点「追问这段」。

**原因**

v150 的 `markAnswerSelection()` 在 `mouseup` 时就写入：

```js
S.pendingAnchor = { kind: 'answer', nodeId, quote, page }
S.pendingParent = nodeId
updateChip()
```

**当时的处理（v151）**

改成：

- 选中只显示「追问这段」浮层
- 点击浮层按钮后才写入 anchor / parent
- 才更新 chip、聚焦输入框

## Bug 5：回滚到 v147 时被错误恢复的行为（v147 回滚后）

**用户原话**

> v147没有“选中右侧回答会立刻挂上追问锚点。”这个bug

**原因**

我回滚时把 `markAnswerSelection` 错误恢复成了 v151 之前的“mouseup 立即挂载”版本。

**修正**

- 当前 v147 源码已恢复为：选中只出浮层，点击浮层才挂追问
- 交接文件 3.2 已改成“正确行为，不是 Bug”
- 快照和安装目录已同步

**结论**

v147 的正确行为不是“选中即挂”，以后回滚不能凭当前代码猜，要以行为验证为准。

## 结论

v147~v151 的 bug 不是一条线性问题，主要是三类：

1. **焦点/选区的时序问题**：窗口焦点、DOM 焦点、未折叠 Selection 三者互相干扰。
2. **UI 状态没有反馈**：追问挂载后 chip / 节点没变化，用户以为按钮坏了。
3. **模型输出不合法**：空化学块、非法 SMILES，前端无法凭空修复。

回滚到 v147 只恢复了旧代码，并没有修掉 1、2 和空化学块；后续若继续做，应单独做焦点状态机，不要再叠加事件补丁。
