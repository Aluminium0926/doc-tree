# v170 · 焦点规则重做：只有鼠标点输入框才聚焦

> 版本：**UI v170 / APP 1.0.60**
> 起因：焦点几乎永远在输入框，方向键翻页用不了；而且"自动回焦"是一层层补丁堆出来的。
> 用户定的规则：**鼠标点输入框区域，是焦点进入输入框的唯一充要条件。**

## 一、删掉了什么

整个 `public/modules/focus.js`（189 行）删除，`app.js` 里 17 处主动搬焦点的调用全部删掉：

| 原来会抢焦点的时机 | 现在 |
|---|---|
| 窗口激活 / 启动后 120/600/1600ms | 不抢 |
| 点任意空白、工具栏、树、文档列表 | 不抢 |
| 点「追问」「用这段提问」「追问这段」 | 只挂引用，不抢 |
| 关闭弹窗 / 确认框 / 搜索条 / 设置 | 不抢 |
| 发送完成、删除完成、导入完成、选图/粘贴完成 | 不抢 |
| 切换文档 | 不抢 |
| 按键兜底（焦点在 body 时敲字自动回焦） | 删除 |
| 输入法首键 229 回焦 | 删除（不再需要，见下） |

保留（且只有这一个）：`#composer` 上的 `pointerdown` → 点输入框区域（空白/正文）聚焦 `#q`；
以及浏览器原生的"点 textarea 聚焦"。

## 二、行为对照

| 操作 | 结果 |
|---|---|
| 打开文档 / 启动应用 | 焦点在 body，不闪光标 |
| 点页面空白、点按钮、点树、切文档 | 焦点留在原处，输入框不会抢回来 |
| 点输入框 | 聚焦，可以打字（唯一入口） |
| 点页面后按 ↑↓ / PageUp/Down / Home/End | 滚动页面 |
| 点页面后按 ←→ | PDF 上一页 / 下一页 |
| 点输入框后按方向键 | 输入框为空时仍让给 viewer；有文字时正常移动光标 |

## 三、为什么这样反而更稳

之前的"丢焦点"问题，本质是自动回焦和浏览器原生行为互相打架（点 A 被搬去 B，用户以为丢了）。
现在没有程序化搬焦点，浏览器怎么给的就怎么留着：

- 中文输入法不再被打断（不再有"删完东西能粘贴不能打汉字"那类问题）；
- 方向键/翻页/选字回归原生；
- 行为可预测：想打字就点一下输入框。

代价：点完工具栏按钮后不会自动回到输入框，需要再点一下输入框才能继续打字。
这是规则的一部分，不是 bug。

## 四、测试（全部按新规则重写）

- 拖选文字、点浮层、点「追问」、切文档、关设置、关确认框、选图、粘贴：都不搬焦点
