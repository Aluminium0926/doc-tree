# v164 · 删除后中文输入法打不进去（原生 confirm 打断 IME）

> 版本：**UI v164 / APP 1.0.54**
> 用户描述：选中回答里的一段文字 → 复制 → 左键点几下让「追问此段」消失 → 点节点「删除」→
> **输入框能粘贴、能删字，就是打不进汉字**

## 一、不是焦点问题

按原步骤在安装版里跑了一遍，逐步记录 `document.activeElement`：

| 步骤 | activeElement | 说明 |
|---|---|---|
| 选中回答文字 | BODY | 选区保留，正常 |
| 点几下空白 | #q | 回焦正常 |
| 点「删除」→ 确认 | #q | 回焦正常 |

焦点一直在 `#q` 上 —— 所以「选不上」不是焦点丢了，是**输入法上不了屏**。
这正是当年 v147 文档里记的那类现象：能粘贴、能删字，中文打不进去。

## 二、根因

删除确认用的是**原生 `window.confirm()`**：

```js
if (!confirm('删除这条追问及其子分支？')) return
```

Electron 里原生模态框会接管窗口的输入上下文，关掉之后渲染进程的 IME 输入上下文没有重新挂回输入框，
于是键盘快捷键（粘贴/删除）正常，IME 的 composition 却送不进去。

## 三、修法

1. 新增应用内确认弹窗 `#confirm`（复用 `.modal` 样式）；`uiConfirm()` 返回 Promise，
   支持 Enter 确认 / Esc 取消 / 点遮罩取消，关闭后自动回焦输入框。
2. 把**所有** 4 处原生 `confirm()` 换掉：
   - 把文档移出列表
   - 解散分组
   - 彻底删除文档
   - 删除追问节点
3. 用测试锁住：删除时 `page.on('dialog')` 必须触发 **0 次**。

## 四、验证（安装版，自动化）

按用户原步骤：

```
打开文档 → 选中回答文字 → Ctrl+C → 点几下空白 → 点「删除」
  → 应用内确认框弹出（原生 dialog 计数 = 0）
  → 点「确定」→ 节点删除、焦点回输入框
  → 输入法提交（CDP Input.insertText，等价于输入法上屏）→ #q = "中文" ✅
```

`test-ui` 新增 4 条（总计 **83** 项）：应用内确认框、无原生 dialog、确认后关闭、回焦。
`npm test` → API 84/84、UI 83/83；安装版 Electron 15/15。

## 五、如果还复现

1. 先确认版本：设置弹窗底部显示 `当前版本 v164 · 1.0.54` —— Electron 不会热更新，**必须重启应用**。
2. 若版本正确仍复现，多半是系统输入法（微软拼音）在模态交互后自身卡住：
   可先切一次输入法（Ctrl+Space）验证。把当时用的输入法名称告诉我，
   我再决定要不要在窗口重新获得焦点时强制重建输入上下文。
