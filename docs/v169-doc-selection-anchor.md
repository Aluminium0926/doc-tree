# v169 · 文档选区：选中只出浮层，点了「用这段提问」才挂引用

> 版本：**UI v169 / APP 1.0.59**
> 现象：在左侧文档里选中一段文字后，「用这段提问」像是被一直触发，点哪都甩不掉。

## 一、真正的原因

`markDocSelection()` 在**选中的那一刻**就把锚点写进状态：

```js
S.pendingAnchor = anchor
S.pendingParent = null
updateChip()                       // chip 立刻出现
showFloat(range, [{ label: '用这段提问', act: 'ask' }])
```

于是：选中文字 → 输入框上方 chip 出现并**一直挂着**；之后不管点哪儿，这次提问都还带着那段引用，
看起来就像「用这段提问」被反复触发。

而右侧回答选区的规则（v151 定下的）是：**选中只弹浮层，点了浮层才挂锚点**。文档这边一直没对齐。

## 二、修法

`markDocSelection()` 改成和回答一致：

```js
showFloat(range, [{
  label: '用这段提问',
  run: () => { S.pendingAnchor = anchor; S.pendingParent = null; updateChip() }
}])
```

- 选中 → 只弹浮层（chip 不出现）
- 点「用这段提问」→ chip 出现，焦点回输入框
- 点别处 → 浮层消失，**什么都不会挂上**
- 高亮模式（`S.hlMode`）行为不变

## 三、测试

`test-ui` 里 PDF 选区用例改成 6 条（总计 **98** 项）：

- 拖选后选区保留、只弹浮层、chip 不出现
- 浮层文案是「用这段提问」
- 点浮层后才挂引用，chip 带页码
- 点浮层后焦点回输入框
- 拖选后直接打字：焦点回输入框、首字符不丢

`npm test` → API 91/91、UI 98/98；Electron 15/15。

## 四、行为变化说明

以前「选中文字 → 直接按回车」会带着引用提问；现在需要先点一下浮层的「用这段提问」。
这是为了和回答选区统一，也避免引用在你不知情的时候一直挂着。
