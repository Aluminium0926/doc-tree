# 安卓 APK 与 HarmonyOS NEXT

## 一、Android APK

### 产物

`mobile/DocTree-android.apk`（约 2.6 MB，minSdk 24 / targetSdk 34，debug 签名）

结构：

- 一个 Activity + WebView
- 进程内起一个本地 HTTP 服务（`127.0.0.1` 随机端口），负责：
  - 提供打包进 `assets/www` 的前端
  - `/proxy/llm`：把 OpenAI 兼容请求转发到用户配置的端点，并将 SSE 原样流回（绕过浏览器 CORS）
- 前端是 `mobile/www`：与桌面版同一套界面，但数据层换成本地版
  - IndexedDB 存文档、追问树、原始文件
  - PDF 用 pdf.js 在浏览器内解析文字层
  - DOCX 用 mammoth browser 版
  - 模型请求走本地代理

### 构建

```powershell
node mobile\build.mjs        # 生成 mobile/www
powershell -File mobile\build-apk.ps1   # 产出 mobile/DocTree-android.apk
```

工具链要求（脚本默认路径）：

- JDK 21（javac + keytool）
- Android SDK：`build-tools;35.0.0`、`platforms;android-34`
- 脚本里 `$sdk = 'C:\dt-sdk'`

> 两个已知坑：
> 1. `aapt2` / `aapt` 读不了含中文的路径，SDK 和构建目录都要放在纯英文路径（脚本会自动把源码搬到 `C:\dt-android-build`）。
> 2. build-tools 34 的 d8 与 JDK 21 编译出的 class 不兼容（NPE），用 **build-tools 35** 的 d8。
> 3. 打包 assets 时用 .NET `ZipArchive` 手动写入，保证 zip 条目是正斜杠（aapt2 在 Windows 上会写成反斜杠）。

### 安装

```bash
adb install -r mobile/DocTree-android.apk
```

或把 APK 传到手机点安装（需要允许"未知来源"）。

### 首次使用

1. 打开 App，点右上角 ⚙ 填 Base URL / API Key / 模型
2. 点「导入文档」选择 PDF / DOCX / MD / TXT
3. 选中文字 → 「用这段提问」→ 发送

数据只存在 App 的 IndexedDB 里，卸载即清空。

### 两个关键实现细节（踩过的坑）

1. **固定端口**：WebView 的 localStorage / IndexedDB 按 origin（协议+域名+端口）隔离。最初本地服务用随机端口，导致每次重启 App 都"数据消失"。现在固定使用 `127.0.0.1:47201`，被占用时才回退到随机端口。
2. **旧版 WebView 兼容**：pdf.js 4.10 依赖 `Promise.withResolvers`（Chrome 119+）。旧机型会直接报错，所以：
   - 页面侧：`mobile/src/polyfills.js`
   - worker 侧：`public/vendor/pdf.worker.wrapper.mjs` 先加载垫片再加载真正的 worker
   - 把 `GlobalWorkerOptions.workerSrc` 指向 wrapper 即可

### 已验证

在 Android 14 模拟器（Chrome 113 内核，比真机老）上实测通过：

```
导入 PDF → 解析文字层 → 渲染页面
提问 → 本地代理转发 → 流式返回（思考过程 4232 字 + 答案）
重启 App → 文档、追问树、配置全部保留
```

## 二、HarmonyOS NEXT

**APK 不能在 HarmonyOS NEXT 上运行**——鸿蒙 NEXT 移除了 AOSP 兼容层，只认 HAP（ArkTS/ArkUI 或 Web 组件）。

同一套前端已经做了两件事来适配：

1. **响应式移动布局**：`mobile/mobile.css`，窄屏下文档区在上、追问树在下，文档库变抽屉
2. **PWA**：`manifest.webmanifest` + `sw.js`，可离线缓存外壳

### 方案 A：浏览器 / PWA（立刻可用）

在鸿蒙浏览器里打开部署好的站点（或本地服务），菜单里「添加到桌面」，即得到接近原生体验的入口。

限制：模型请求仍需要同源代理（浏览器 CORS），所以要么：

- 用带 `/proxy/llm` 的服务端（本仓库 `server.mjs` 或手机上的本地服务）
- 或部署一个只做转发的轻量代理

### 方案 B：ArkTS Web 壳（需要 DevEco Studio）

在鸿蒙工程里放一个 `Web` 组件加载同一套前端资源（`rawfile`），并实现同等能力的本地代理：

```ts
Web({ src: $rawfile('index.html'), controller: this.controller })
  .javaScriptAccess(true)
  .domStorageAccess(true)
  .fileAccess(true)
```

- 前端资源直接复用 `mobile/www`
- 模型代理需要在 ArkTS 侧用 `http` 模块实现 `/proxy/llm`，或让前端走鸿蒙原生请求（把 `mobile/src/llm.js` 换成 `@ohos.net.http`）
- 存储可用 `preferences` / `relationalStore` 替代 IndexedDB，或继续用 Web 组件的 localStorage/IndexedDB

> 本项目没有内置 HarmonyOS 工程（需要 DevEco Studio + HarmonyOS SDK 才能构建 HAP），方案 B 是移植路径说明。

## 三、与桌面版的差异

| 能力 | 桌面版 | 安卓 APK |
|---|---|---|
| 文档解析 | Node 端 pdfjs / mammoth | 浏览器内 pdfjs / mammoth |
| 存储 | 文件系统 `data/` | IndexedDB |
| 模型请求 | 服务端直接请求 | 本地代理转发（同源） |
| 导出 Markdown | 服务端下载 | JS 桥接写入「下载」目录 |
| 中文路径 | Electron 限制，需启动器 | 无此问题（APK 内部路径固定） |
